# orgFiles

**디자인부터 업무 문서까지, 내 컴퓨터의 모든 파일을 한곳에 모으는 Windows 앱입니다.**

Eagle의 폴더·태그·갤러리 관리 방식에서 영감을 받아 독립적으로 개발했습니다. Eagle 라이브러리와 호환되는 제품이나 복제품은 아닙니다. 로그인이나 서버 없이 로컬에서 동작하며, 가져온 파일은 원본을 유지하고 보관함에 복사합니다.

## 설치

1. [최신 Windows 설치 파일](https://github.com/mycodehive/orgFiles/releases/latest)에서 `orgFiles-Setup-1.0.0-x64.exe`를 다운로드합니다.
2. 설치 파일을 실행하고 설치 위치를 선택합니다. Windows 10/11 **64비트(x64)** 환경을 대상으로 합니다.
3. 시작 메뉴 또는 바탕화면의 **orgFiles**를 실행합니다. Node.js·Python·별도 서버 설치는 필요 없습니다.
4. **파일 가져오기** 또는 **폴더 가져오기**를 누르거나 앱에 파일을 끌어다 놓습니다.

초기 배포본은 코드 서명 인증서가 없어 Windows SmartScreen 경고가 나타날 수 있습니다. 저장소와 배포 경로를 확인하고 배포된 SHA-256과 비교하세요. 설치 제거 시 사용자 보관함은 유지됩니다.

## 주요 기능

- 이미지·디자인 소스·PDF·Word·Excel·PowerPoint·한글 등 **확장자에 관계없이 일반 파일 보관**
- 폴더 및 하위 폴더, 한 파일의 복수 폴더 분류, 태그·메모·별점·즐겨찾기
- 갤러리·목록 보기, 카드 크기 조절, 파일 유형·최근 7일·미분류·태그 없음 필터
- 파일명·제목·태그·메모·추출 가능한 문서 본문 검색. 공백으로 구분한 검색어는 모두 포함하는 항목을 찾습니다.
- SHA-256 내용 중복 감지. 같은 내용은 한 번만 저장하며, 현재 폴더 분류는 기존 항목에 추가합니다. 이름이 같아도 내용이 다르면 별도로 보관합니다.
- 선택 파일 일괄 태그·폴더 편집, 파일 내보내기, 연결 프로그램 열기, 탐색기 위치 보기
- 휴지통·복원·확인 후 영구 삭제. 원본 파일은 변경하거나 삭제하지 않습니다.
- 독립된 여러 보관함 생성·전환, 파일과 메타데이터가 포함된 **전체 백업**
- 한국어 인터페이스, 오프라인 사용

## 미리보기 지원 범위

| 형식 | 앱 안에서 보는 내용 | 검색 가능한 내용 |
|---|---|---|
| JPG·PNG·GIF·WebP·SVG·BMP·AVIF·ICO | 이미지 | 파일명·태그·메모 |
| PDF | PDF 뷰어. 환경에 따라 연결 프로그램 사용 | 파일명·태그·메모 |
| TXT·MD·CSV·TSV·JSON·코드 | 텍스트 | 파일명·태그·메모·본문 |
| DOCX·XLSX·PPTX·HWPX·ODT·ODS·ODP | 추출한 텍스트 | 파일명·태그·메모·추출 본문 |
| MP4·WebM / MP3·WAV·OGG 등 | 재생 환경의 코덱이 지원하는 영상·오디오 | 파일명·태그·메모 |
| HWP·DOC·XLS·PPT·PSD·AI·FIG·ZIP 등 | 형식 표시, OS가 지원하면 섬네일. 연결 프로그램으로 열기 | 파일명·태그·메모 |

문서 본문 미리보기는 원본 레이아웃 렌더링이 아닙니다. 서식·이미지·도표·수식·엑셀 셀 구조는 원본 프로그램으로 확인하세요. 최대 30만 자, 압축 문서 입력 32MB, XML 항목 8MB/총 24MB 제한을 적용합니다. 이미지 OCR, PDF 본문 추출, Eagle 라이브러리 가져오기, 클라우드 동기화, AI 자동 분류는 현재 지원하지 않습니다. PSD·AI·HWP 전용 미리보기 엔진을 포함하지 않습니다.

스크립트·실행 파일·바로가기는 보관할 수 있으나 앱에서 실행하지 못하게 제한합니다. HTML·XML·코드는 실행하지 않고 텍스트로 표시합니다. 가져오기 결과에서 실패한 파일과 이유를 확인할 수 있습니다.

## 사용법

- 파일 클릭 → 오른쪽에서 제목·태그·메모 편집 → **변경사항 저장**
- 태그는 `계약서, 연구, 2026`처럼 쉼표로 구분합니다.
- 폴더 옆 **＋**로 폴더 생성. 폴더를 **오른쪽 클릭**하면 하위 폴더·이름 변경·삭제를 할 수 있습니다.
- 파일 상세의 **폴더 편집**으로 하나 이상의 폴더를 지정합니다. 폴더 삭제는 분류만 없애며 파일은 유지합니다.
- `Ctrl+클릭`: 여러 파일 선택, `Shift+클릭`: 범위 선택, `Ctrl+A`: 현재 검색 결과 전체 선택
- `Ctrl+K`: 검색, `Ctrl+O`: 파일 추가, `Space`: 미리보기, `Enter`: 연결 프로그램 열기, `Delete`: 휴지통, `Esc`: 선택 해제
- 상단 설정 **⚙ → 전체 백업 만들기**로 보관 파일과 태그·메모·폴더를 함께 복사합니다.
- 백업을 복원하려면 **⚙ → 다른 보관함 / 전체 백업 열기**에서 백업 폴더를 선택하세요. 기존 보관함과 병합하지 않고 별도 보관함으로 엽니다.
- 휴지통의 중복 파일은 다시 가져와도 자동 복원되지 않습니다. 휴지통에서 복원하세요.

## 데이터 저장

기본 보관함은 Windows 사용자 **문서 폴더의 `orgFiles Library`** 입니다. 다른 위치는 설정에서 새 보관함을 만들거나 열어 선택합니다.

```text
orgFiles Library/
  catalog.json             # 파일 목록·태그·메모·폴더·검색 텍스트
  catalog.previous.json    # 직전 정상 목록
  files/                   # UUID로 저장한 파일 복사본
  previews/                # 다시 만들 수 있는 섬네일 캐시
```

파일 내보내기는 선택한 파일만 원래 파일명으로 복사합니다. 같은 이름이 이미 있으면 번호를 붙이고 덮어쓰지 않습니다. **파일 내보내기와 전체 백업은 다릅니다.** 전체 보관함을 백업하려면 설정의 전체 백업 기능을 사용하세요. 파일은 암호화하지 않습니다. 원본 경로와 검색용 텍스트도 로컬 목록에 저장됩니다.

동일 보관함을 여러 프로그램·컴퓨터에서 동시에 수정하지 마세요. 실행 중 `catalog.json`이나 `files/`를 수동 수정하지 마세요. 보관함 위치 설정은 `%APPDATA%/orgFiles/settings.json`에 저장됩니다(실제 Electron 앱 이름에 따라 `orgfiles`일 수 있음). 목록 읽기에 실패하면 이전 목록을 사용하거나 시작을 중단하며 빈 목록으로 덮어쓰지 않습니다.

## 개발 언어와 구조

**JavaScript + Electron**을 사용합니다. HTML/CSS로 화면을 만들고 Electron의 메인 프로세스가 Windows 파일시스템·파일 선택창·연결 프로그램을 처리합니다. 네이티브 SDK를 따로 배울 필요가 적고 Windows 설치본에 실행 환경을 함께 포함할 수 있어 첫 데스크톱 프로젝트에 선택했습니다.

```text
src/main.cjs       # Electron 창·프로토콜·검증된 IPC·네이티브 작업
src/preload.cjs    # 화면에 공개하는 기능별 브리지
src/library.cjs    # 복사·해시·분류·순차 저장·백업
src/extract.cjs    # 크기 제한을 적용한 문서 XML/텍스트 추출
src/formats.cjs    # 유형·미리보기·외부 실행 제한
src/index.html     # 한국어 3열 화면
src/app.js         # 탐색·검색·편집·미리보기
src/styles.css    # 독립적인 다크 UI
```

Node.js 22 이상을 설치한 후:

```powershell
git clone https://github.com/mycodehive/orgFiles.git
cd orgFiles
npm ci
npm start
npm test
npm run test:ui
npm run dist:win
```

결과: `dist/orgFiles-Setup-1.0.0-x64.exe`. 배포는 **Windows 환경의 GitHub Actions**가 담당합니다. main/PR에 테스트·빌드를 수행하고 `v*` 태그에서 설치본·SHA-256을 Releases에 게시합니다. `ORGFILES_LIBRARY` 환경변수로 테스트용 보관함 경로를 지정할 수 있습니다.

보안은 [Electron 공식 권고](https://www.electronjs.org/docs/latest/tutorial/security)에 따라 context isolation·renderer sandbox·CSP·IPC 송신자 검사·별도 파일 미리보기 origin·허용 형식 프로토콜을 적용합니다. 설치 패키징은 [electron-builder NSIS](https://www.electron.build/nsis/)를 사용합니다. 로컬 JSON 목록은 소규모 개인 보관함용이며 대규모 자료(수만~수십만 파일)는 SQLite 인덱스·백그라운드 처리로 확장하는 것이 적합합니다.

## 검증

`npm test`: 한글 경로, 원본 보존, 해시 중복, 동일 이름 다른 파일, 분류·태그·휴지통·복원·영구 삭제, 전체 백업 재개방, 덮어쓰기 없는 내보내기, 경로 검증·심볼릭 링크, 악성 XML·대용량 압축 문서, 목록 손상 복구, 동시 저장.

`npm run test:ui`: 실제 Electron 프로세스에서 가져오기·본문 검색·메타데이터 저장·미리보기·정렬 화면·휴지통·재시작 보존·프로토콜 접근 제한·실행 파일 차단·HTML 비실행을 확인합니다.

Windows CI는 NSIS 무인 설치 → 설치된 앱 실행 → 보관함 초기화 → 제거 시 데이터 보존까지 확인합니다. 실제 사용자 PC의 SmartScreen·파일 연결 프로그램·드라이버·특정 PDF/미디어 코덱은 별도 확인이 필요합니다.
